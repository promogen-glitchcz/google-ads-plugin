# Google Ads OAuth setup

Use this skill any time the user needs working credentials for the Google Ads plugin.

## What you need from the user

Three values from a Google Cloud OAuth client (Web or Desktop type):
1. `GOOGLE_ADS_CLIENT_ID` (looks like `NUMBER-RANDOM.apps.googleusercontent.com`)
2. `GOOGLE_ADS_CLIENT_SECRET` (looks like `GOCSPX-...`)
3. `GOOGLE_ADS_DEVELOPER_TOKEN` (a 22-character string from Google Ads UI -> Tools -> API Center)

The refresh token is generated by the wizard, not asked from the user.

## Setup flow

1. Read `.secrets/.env`. If client_id, client_secret, developer_token are present, jump to step 3.
2. If any are missing, ask user for them. Save them to `.secrets/.env` (the file is gitignored).
3. Run the OAuth wizard:
   ```bash
   python3 scripts/oauth_setup.py
   ```
   - It opens a browser, user logs in, consents, redirected to localhost:8765.
   - It writes `GOOGLE_ADS_REFRESH_TOKEN` to `.secrets/.env`.
4. Verify by running `python3 scripts/list_accounts.py`. If accounts list, setup is done.

## Common errors and what they mean

**`unauthorized_client`** - The refresh_token in .env was issued for a DIFFERENT client_id. Refresh tokens are bound to the client that minted them. Fix: rerun `python3 scripts/oauth_setup.py`.

**`invalid_grant`** - Refresh token was revoked, expired (testing-mode 7-day window), or the user changed Google password. Fix: rerun `python3 scripts/oauth_setup.py`.

**`redirect_uri_mismatch`** during the wizard - The OAuth client doesn't have `http://localhost:8765` as an authorized redirect URI. Tell the user to:
   1. Go to Google Cloud Console -> APIs & Services -> Credentials
   2. Edit their OAuth 2.0 Client ID
   3. Under "Authorized redirect URIs" add `http://localhost:8765`
   4. Save and rerun the wizard

**`access_denied`** - User clicked Cancel during consent. Just rerun.

**`OAuth client not found`** - client_id is wrong or the OAuth client was deleted in Google Cloud. Verify client_id.

**`DEVELOPER_TOKEN_NOT_APPROVED` (after auth works)** - Auth is fine but the developer token isn't approved for the scope of usage. Tell user to request Basic or Standard access in Google Ads UI -> Tools -> API Center. Until approved, only test customer IDs work.

**`USER_PERMISSION_DENIED` after auth works** - The Google account that approved consent doesn't have any Google Ads access. They need to be invited to the Google Ads account first, or to a manager (MCC) above it.

## Testing-mode vs published OAuth client

In Google Cloud Console -> OAuth consent screen, the publishing status matters:
- "Testing": refresh tokens expire after 7 days, max 100 users
- "In production": refresh tokens don't expire, available to anyone

For long-lived automation, publish the consent screen.

## Where credentials live

```
.secrets/.env    <- gitignored, never committed
```

If user prefers per-machine config: `~/.config/google-ads-plugin/.env` is also read (lower precedence than process env).
